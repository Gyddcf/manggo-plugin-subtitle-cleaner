# 字幕碎片清洗 —— Manggo 插件

纯本地清洗截图 OCR 英文字幕里的碎片字符。**不联网、不调用模型、毫秒级**。

## 为什么需要它

截图 OCR 经常把界面边框、图标、光标识别成 `{ }` `[ ]` `|` `_` `~` 这类碎片，混进英文原文里。后果有两个：

1. 译文里留着这些符号；
2. 更麻烦的是 —— Manggo 的**源语言检测被带偏**。平均100 条历史记录里有 12 条 把英文判成了德语/法语/西班牙语/意大利语，全是「短英文 + 连字符/下划线/斜杠」这种形态：

| OCR 出来的原文 | 被判成 | 结果 |
| --- | --- | --- |
| `-quicktext` | 德语 | -快速文本 |
| `JavaScript` | 法语 | JavaScript |
| `config_json` | 法语 | 配置 json |

这个插件在文本进翻译之前先把它洗干净，上面两类问题一起解决。

## 性能

实测 node v26 ：

| 场景 | 单次耗时 |
| --- | --- |
| 典型字幕（39 行 / 620 字符） | **0.067 ms** |
| 整页文档（780 行 / 12419 字符） | **1.27 ms** |

对比：OCR 本身要几十到几百毫秒。清洗开销可以忽略不计。

## 清洗规则

**整行丢弃**

- 纯符号行、纯数字行、单字符行、同字符重复行（`=====`、`aaa`）
- 字幕时间轴行 `00:01:23,456 --> 00:01:24,000`

**字符级删除**

- 硬噪声：`| ~ { } ^ ` \` 直接删（`wor{}d` → `word`，不插空格）
- 下划线当分隔符：`my_function` → `my function`
- 代码类符号（可关）：`[ ] < > = + * # @ $ %`
- HTML 标签整对删：`<i>Hello</i>` → `Hello`
- 空括号对、只含符号的括号、夹在正文里的图标单字（`日` `目` `口` `○` `●`）

**行内修复**

- 括号内侧空白：`Hello( world )` → `Hello(world)`
- 重复标点折叠：`!!!!` → `!`
- 全角转半角
- 行首/行尾游离符号剥离（保留引号、句末标点、中文标点、连字符、音乐符号）

**拼回断句**

- 连字符断词：`inter-` + `national` → `international`
- 上一行够长（默认 ≥20 字符）、没句末标点、下一行小写开头 → 拼成一句

**URL 保护**：`https://...` 先抽出占位，清洗完再放回，不会被符号规则打碎。

## 安装

1. 打开 Manggo → 设置 → **插件管理** → 安装
2. 选择 `dist/字幕碎片清洗.mplugin`
3. 到「翻译服务」页面添加「字幕碎片清洗」

> 注意：插件系统是 Manggo **Pro** 功能（免费版没有插件管理页）。

## 怎么用

这个插件**只清洗、不翻译**，所以正确的用法是让它在翻译链路里当「前处理」：

### 用法 A：当翻译服务用（推荐先试）

在翻译服务列表里添加「字幕碎片清洗」，它会返回清洗后的干净原文。配合 Manggo 的**并排显示**功能，一边看清洗结果、一边看内置翻译服务的译文。

### 用法 B：划词助手「清洗碎片」

选中任意文字 → 划词助手 → 点「清洗碎片」，原地替换成干净版本。适合已经复制到编辑器里的文本。

## 配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 删掉代码类符号 | 开 | `_ [ ] < > = + * # @ $ %` 直接删。看代码截图时建议关掉 |
| 丢弃短行阈值 | 1 | 一行英文字母数 ≤ 此值就当碎片丢。填 2 会连 `hi`、`ok` 一起丢 |
| 拼回被拆断的句子 | 开 | 断句拼回、连字符断词接上 |
| 拼句的最小行长 | 20 | 上一行至少这么长才参与拼句。调大更保守 |
| 丢掉字幕时间轴行 | 开 | `00:01:23,456 --> ...` 整行删 |
| 保留段落空行 | 开 | 关掉则所有空行压成单换行 |
| 额外要删的字符 | 空 | 逗号分隔，如 `※,●,→` |

## 已知取舍

- **纯数字行会被丢**。字幕里的年份、价格、时间单独成行时会消失。这是为了清时间轴和页码残留付出的代价；如果介意，把「丢弃短行阈值」设为 0 只能挡住单字母，挡不住纯数字行。
- **不处理英文里混中文句号**（`This is fine。`）—— 那是正常字幕里可能出现的中英混排，不动它。
- **不做语言检测**。源语言判错的问题靠「洗干净文本」间接缓解，不是直接修复。真要根治得换 OCR 引擎或换大模型翻译。
